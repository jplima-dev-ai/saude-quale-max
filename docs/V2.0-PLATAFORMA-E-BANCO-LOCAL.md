# Saúde Qualimax v2.0 — Plataforma comercial com banco local

## Objetivo
A v2.0 transforma a landing page em uma plataforma de descoberta de produtos com estado persistente, mantendo compatibilidade com hospedagem estática como GitHub Pages.

## Banco de dados
A aplicação utiliza IndexedDB no navegador. O arquivo `data/produtos.json` continua sendo a fonte editável do catálogo e é sincronizado para o banco local no carregamento.

Stores:
- `produtos`: cópia local do catálogo;
- `favoritos`: IDs favoritados;
- `interesse`: lista de produtos que o visitante quer consultar;
- `historico`: produtos vistos recentemente;
- `meta`: metadados locais.

Quando IndexedDB não está disponível, existe fallback local para preservar funcionalidade básica.

## Recursos v2.0
- Favoritos persistentes sem login.
- Lista de interesse persistente.
- Envio da lista inteira ao WhatsApp com contexto.
- Produtos vistos recentemente.
- Produtos relacionados calculados por categoria, tags, formato e características.
- Sugestões de busca nativas por produto, categoria e tags.
- Assistente Qualimax com acesso às escolhas e ao último produto visualizado.
- Assistente capaz de adicionar produtos à lista.
- Páginas estáticas individuais para todos os produtos.
- Compartilhamento de produto por Web Share API ou cópia de link.
- PWA leve com manifest e service worker.
- Miniaturas continuam sendo usadas em listagens; imagem grande é reservada para detalhes.

## Privacidade
Favoritos, histórico e lista ficam no dispositivo. Esses dados não são enviados à loja automaticamente. O envio acontece somente quando o visitante aciona o WhatsApp.

## Limites desta arquitetura
IndexedDB é um banco local do navegador, não um banco central da empresa. Ele não substitui backend para estoque em tempo real, pedidos, autenticação, pagamento ou sincronização entre dispositivos. Esses recursos exigirão backend e banco remoto em uma evolução futura.
